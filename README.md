# Winfiles

A modular PowerShell 7 environment for Windows. It mirrors the behavior and
safety model of the companion `dotfiles` repository while using native Windows
tools: Oh My Posh, PSReadLine, WinGet, FNM, PowerShell modules, and generated
native completions.

## Companion repository

> [!TIP]
> **Using macOS, Linux, or WSL?**
>
> See [`dotfiles`](https://github.com/pablousx/dotfiles) for the Zsh-based
> counterpart to this Windows configuration.

## Scope

- PowerShell 7 is the managed interactive shell.
- WSL continues to use `dotfiles`.
- Windows PowerShell 5.1 profiles are not modified.
- Windows Terminal's complete `settings.json` is not managed.
- Machine-specific integrations belong in a local, untracked profile hook.

## Installation

Clone the repository anywhere and run setup from PowerShell 7:

```powershell
git clone https://github.com/pablousx/winfiles.git
Set-Location winfiles
.\setup.ps1
```

The zero-argument workflow prompts for every component, displays a summary,
and asks for confirmation. Answering “no” leaves that component unchanged.
Setup never changes the PowerShell execution policy.

The installer can also run non-interactively:

```powershell
.\setup.ps1 -All
.\setup.ps1 -Core -Fnm -PowerShellModules -ShellProfile -Completions
.\setup.ps1 -ConfigureModules
.\setup.ps1 -ShellProfile -MigrateExistingProfile
.\setup.ps1 -All -WhatIf
```

`-MigrateExistingProfile` is deliberately opt-in. It backs up affected
profiles and removes only recognized FNM, Oh My Posh, PowerToys
CommandNotFound, and Inshellisense initializers that winfiles will replace.
Unrelated content, including SSH synchronization, remains untouched.

The default Node.js version is `24.12.0`:

```powershell
.\setup.ps1 -Fnm -NodeVersion 24.12.0
```

## Components

- Core tools — installs missing tools from the IDs in `config/packages.psd1`
  using WinGet. Existing commands are reused regardless of how they were
  installed.
- FNM — installs FNM only when absent, then installs and selects Node.js.
- PowerShell modules — installs exact versions from `config/modules.psd1`.
- Profile loader — adds one marked, repository-relative block to
  `$PROFILE.CurrentUserAllHosts`.
- Completions — caches completion scripts generated by locally installed
  `gh`, `fnm`, and `deno`, and registers WinGet completion.

New packages and module versions installed by setup are recorded under the
current user's local application data. Pre-existing software is never claimed
as winfiles-owned.

## Configuration

The managed startup order is:

1. validated settings;
2. environment and PATH entries;
3. PSReadLine history, prediction, and editing behavior;
4. aliases and helper functions;
5. cached native completions;
6. optional modules, FNM, PSFzf, and Inshellisense;
7. Oh My Posh;
8. the machine-local profile hook.

Run `.\setup.ps1 -ConfigureModules` to create the ignored
`config/settings.psd1`. Supported values are:

```powershell
@{
    DisableAliases     = $false
    DisablePrompt      = $false
    DisableModules     = $false
    DisableCompletions = $false
    DisablePredictions = $false
    DisableFzf         = $false
}
```

Literal environment variables override the file for one-off sessions:

```powershell
$env:WINFILES_DISABLE_PROMPT = 'true'
$env:WINFILES_DISABLE_MODULES = 'true'
pwsh
```

Only the strings `true` and `false` are accepted. Other values fail early
instead of being evaluated.

Machine-specific PowerShell belongs at:

```text
%USERPROFILE%\.config\winfiles\local.ps1
```

Set `WINFILES_LOCAL_PROFILE` to use a different file.


The npm, pnpm, and Yarn shortcuts are functions, so additional arguments are
passed through correctly. `upload_winfiles` stages tracked files only, refuses
detached HEADs, avoids empty commits, and stops when commit or push fails.

## Safe removal

Run the interactive uninstaller:

```powershell
.\uninstall.ps1
```

Or select components explicitly:

```powershell
.\uninstall.ps1 -ShellProfile
.\uninstall.ps1 -Packages -PowerShellModules
.\uninstall.ps1 -All -WhatIf
```

Removal defaults to “no” and requires typing `uninstall` unless `-Force` or
`-WhatIf` is used. Only the marked profile block and recorded owned packages
or module versions are eligible. Profile backups created during migration are
not deleted or automatically restored.

## Validation

Install the pinned development modules through setup, then run:

```powershell
.\setup.ps1 -PowerShellModules
.\tests\Invoke-Checks.ps1 -RequireTools
```

Checks cover PowerShell parsing, PSScriptAnalyzer, Pester tests, settings
validation, environment overrides, profile preservation, migration boundaries,
loader idempotence, prompt JSON, hard-coded paths, and whitespace. CI runs the
same checks on Windows.

## Porting decisions

Powerlevel10k maps to the repository-owned Oh My Posh theme. Antidote plugins
map to PSReadLine, PSFzf, Terminal-Icons, native PowerShell helpers, and
tool-generated completions. Zsh global aliases and ZLE command rewriting are
not reproduced because they do not have reliable PowerShell equivalents.
